# 🛡️ JWTs: The Passport of the Internet

**Date:** Dec 1, 2025 | **Mood:** 🔐 Cryptographic

## The Problem

Imagine carrying a simple membership card.

It lets you enter a building, but it doesn't prove who issued it or whether someone has tampered with it.

A JWT (JSON Web Token) is different.

It's a **digitally signed token** that securely carries information about a user or system. Instead of asking the server to look up the user's identity on every request, the token itself contains trusted information that can be verified.

---

## The Analogy: A Government Passport 🛂

I like to think of a JWT as a government-issued passport.

- The passport contains important information about you.
- It is issued by a trusted authority.
- It includes security features that are difficult to forge.
- If someone changes any information inside it, the passport is no longer valid.

A JWT works in a very similar way.

---

## The Anatomy of a JWT

A JWT consists of **three Base64URL-encoded sections** separated by dots (`.`).

```
Header.Payload.Signature
```

Example:

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.
eyJzdWIiOiIxMjM0NTY3ODkwIiwibmFtZSI6Ik1hdmVSaWNrIiwiYWRtaW4iOnRydWV9.
SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
```

---

### 1. Header

The Header describes the token itself.

Typical information includes:

- Token type (`JWT`)
- Signing algorithm (`HS256`, `RS256`, etc.)

Think of it as the cover of a passport.

---

### 2. Payload

The Payload contains **Claims**.

Claims are pieces of information such as:

- User ID
- Username
- Roles
- Permissions
- Expiration time (`exp`)
- Issued time (`iat`)

Example:

```json
{
  "sub": "12345",
  "name": "MaveRick",
  "role": "Admin",
  "exp": 1764019200
}
```

Think of this as the identity page inside a passport.

> **Important:** The payload is **encoded, not encrypted**. Anyone holding the token can decode and read it. Sensitive information should never be stored inside a JWT.

---

### 3. Signature

The Signature protects the integrity of the token.

It is generated by combining:

- Header
- Payload
- Secret key (HS256) or Private Key (RS256)

If anyone changes even one character in the Header or Payload, the Signature becomes invalid.

Think of it as the official security seal on a passport.

---

## The Magic Behind JWTs ✨

Imagine someone edits the Payload and changes:

```
Role: User
```

to

```
Role: Admin
```

The Signature immediately becomes invalid because it was calculated using the original data.

When Apigee or another API Gateway validates the Signature, the modified token is rejected.

This protects the token from tampering.

---

## Why Apigee Uses JWTs

Apigee can validate JWTs before forwarding requests to backend services.

Common checks include:

- ✅ Verify the digital signature.
- ✅ Ensure the token has not expired.
- ✅ Validate the issuer (`iss`).
- ✅ Validate the intended audience (`aud`).
- ✅ Check required scopes or claims.
- ✅ Reject invalid or modified tokens with **401 Unauthorized**.

Because the token is self-contained, backend services often don't need to query a database to verify the user's identity for every request.

---

## JWT vs API Key

| API Key | JWT |
|---------|-----|
| Identifies the calling application | Represents a user or system |
| Usually static | Usually short-lived |
| Contains little or no user information | Contains claims about the user |
| Simple authentication | Rich identity and authorization information |
| Cannot detect tampering | Digitally signed to detect tampering |

---

## One Important Lesson

A JWT is **not encryption**.

It is a **digitally signed token**.

Anyone can decode the Header and Payload.

The Signature simply proves that the contents have not been altered since they were issued.

---

## TL;DR

A JSON Web Token (JWT) is a digitally signed token that securely carries claims about a user or system.

API gateways such as Apigee validate the token's signature, expiration, issuer, audience, and claims before allowing requests to reach backend services. JWTs provide a secure, stateless way to identify and authorize requests without repeatedly querying backend systems.
